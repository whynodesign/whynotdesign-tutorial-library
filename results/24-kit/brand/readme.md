# 焙曲 / TONEROAST brand kit

> **CONCEPT / EXAMPLE ONLY.** 焙曲 / TONEROAST is a fictional test brand made by whynotdesign to try the
> "agentic brand kit" structure. Nothing here is commercial final art. **No trademark search has been done**
> on either name (only an informal web check on 2026-10-31). Roast data in the examples is invented.

The identity and print/marketing layer of TONEROAST, a Taiwanese small-batch, charcoal-roasted oolong,
packaged so an agent (Claude, Cursor, any coding or image agent) can read it and make new work:
packaging fronts, posters, social posts, short brand motion, web sections.

There is nothing you must run to *use* the kit. It is a set of files. Two small scripts exist only for
*changing* it (see "The files that hold the values").

The structure follows Little Plains' published Sonata kit (agentic.littleplains.com, Sept 2026):
`readme` + `magic_trick` + `how-to-prompt`, `agent/verbal/`, `agent/visual/`, one JSON for values,
generated CSS, assets, components. What we added for a tea brand: `packaging.md`, CMYK/spot estimates,
an AI-image prompting section, and a code-rendered anchor image.

## Where to start

Read `magic_trick.md` first. It names the one thing that makes a surface TONEROAST and not
"a tasteful beige tea label".

Then, depending on what you are making:

| You are making | Read, in this order |
| --- | --- |
| Any copy (headline, label text, caption, post) | `agent/verbal/voice-and-tone.md`, `agent/verbal/concepts.md` (whitelist), then `agent/visual/typography.md` |
| A packaging front / label / sachet | `magic_trick.md`, `agent/visual/packaging.md`, `agent/visual/layout.md`, `agent/visual/color.md`, `agent/verbal/concepts.md` |
| A poster or one-sheet | `magic_trick.md`, `agent/visual/graphic-elements.md` (the Roast Score), `agent/visual/layout.md`, `agent/visual/typography.md` |
| A social card | `agent/visual/layout.md`, `agent/visual/typography.md` (numeral on the stave), `agent/visual/color.md` |
| Brand motion (logo sting, 5 s unit, title entry) | `agent/visual/motion.md`, `agent/visual/motion.json`, `product/components/motion-unit.html` |
| Anything with the logo | `agent/visual/brandmark.md` and `agent/visual/assets/logos/` |
| Anything with photography or AI imagery | `agent/visual/art-direction.md`, then `how-to-prompt.md` |
| A prompt for an image or video model | `how-to-prompt.md` (templates, negative list, QA) |
| Print files (CMYK, spot, bleed, finishes) | `agent/visual/packaging.md`, `agent/visual/color.md` |
| Code (HTML/React) | `agent/visual/tokens.css`, `agent/visual/fonts.css`, `../product/components/` |

If a rule does not cover your case, each document ends with **"When the rules don't cover it"**.
Use that, and write down the call you made so a human can review it.

## The files that hold the values

`agent/visual/visual-system.json` is the only place a visual number lives: colour (HEX, CMYK estimate,
Lab target), type, spacing, radius, mark geometry, the Roast Score, layout and motion.
`tokens.css`, `motion.json` and `product/components/motion.js` are generated from it by
`tools/build_tokens.py`; every logo SVG is generated from it by `tools/make_marks.py`.

Markdown files carry rules and reasons and name values by **token name only**. If you find a hex or
a millimetre value in a Markdown file that disagrees with the JSON, the JSON wins; report the drift.

To change a value: edit the JSON → `python3 tools/build_tokens.py` → `python3 tools/make_marks.py`
→ re-render screenshots (`tools/render.sh`) → commit all outputs together.

## Using the tokens

```html
<link rel="stylesheet" href="brand/agent/visual/fonts.css" />
<link rel="stylesheet" href="brand/agent/visual/tokens.css" />
```
Load `fonts.css` first. Plain CSS, no build step. `product/components/stave.js` draws the stave,
level marks and the Roast Score from these tokens.

| Latin wordmark | Lexend Exa (variable; use 500) | SIL OFL 1.1, Reserved Font Name "RevReading Lexend" | Yes, `fonts/LexendExa-VariableFont_wght.ttf` + `OFL-lexendexa.txt` | https://fonts.google.com/specimen/Lexend+Exa |
| Numerals / labels | DM Mono Regular, Medium | SIL OFL 1.1 | Yes, `fonts/DMMono-*.ttf` + `OFL-dmmono.txt` | https://fonts.google.com/specimen/DM+Mono |

- OFL 1.1 allows commercial use, embedding in documents/apps/web, and redistribution with your work.
  It does not allow selling the font files on their own, and a modified font may not use a Reserved Font Name.
- **CJK fonts are not bundled** (file size, and a rule we keep for every client kit: Chinese fonts are
  referenced, never shipped, so licence status is always checked at the source). Install them from the links above.
- The logo SVGs are outlined from these fonts, so they need no font installed. Outlined artwork made with an
  OFL font is not "Font Software" and can be used freely.
- These faces are **test choices made by the lab, not the final brand typography**. The studio
  (何宇軒) makes the final pick; if a commercial face is chosen, record its licence here.

More detail: `agent/visual/fonts/FONTS.md`.
